# 常见问题与修复经验

> 本项目历史上遇到的问题、根因与修复方案，按时间顺序沉淀。

## 计费幂等性

**问题**：前端重试或流式中断时，额度被重复扣减。

**根因**：没有用 `runId` 记录每次调用。

**修复**：通过 `billing_usage_record` 表记录 `runId`，每次扣减前先查是否已记录。

## BFF Mock 陷阱

**问题**：`node2` 调用 Java 接口时，Mock 返回假数据导致前端表现与真实后端不一致。

**根因**：开发阶段为了隔离，用了 Mock 实现。

**修复**：`node2` 必须走真实 Java 接口，确保 `http-java-domain-client.ts` 正确透传用户身份。

## Flyway 状态不一致

**问题**：Flyway 历史记录与业务表状态冲突，导致 500 错误。

**根因**：历史迁移脚本被修改但未重新执行，或环境数据库状态被手动污染。

**修复**：Drop 相关表后重启服务触发重新迁移，或修正迁移脚本后重新 apply。

## 模板文案污染记忆

**问题**：记忆沉淀中包含前端注入的提示词前缀（如"我想从..."），不纯净。

**根因**：归一化阶段未彻底剔除前端占位模板文案。

**修复**：收紧 Java 侧分片长度阈值，在 Fallback 分片中引入语义清洗逻辑。归一化阶段彻底剔除提示词前缀。

## Markdown 渲染间距过大

**问题**：SSE 输出 Markdown 内容行间距过高，信息密度低。

**根因**：Markdown 容器继承了全局 `pre-wrap` 样式。

**修复**：在 `ChatMessageMarkdown.tsx` 中配合 `globals.css` 强制重置为 `white-space: normal`，设置紧凑行高 `1.48` 和段间距 `5px`。

## JDK 环境识别失败（macOS）

**问题**：Gradle 无法识别 Homebrew 安装的 openjdk@21。

**根因**：Homebrew 安装路径非 Gradle 默认扫描路径。

**修复**：手动设置 `JAVA_HOME`：
```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
```

## 聊天 UI 气泡暴露内部 prompt

**问题**：从引导弹窗进入聊天时，用户气泡显示的是内部 kickoff prompt，不适合用户阅读。

**根因**：`launchIntentConversation` 直接将 `kickoffPrompt` 作为用户可见文本传入消息。

**修复**：将 `SuggestionSeed` / `SuggestionChip` 拆分为 `visibleText`（用户可见）和 `kickoffPrompt`（后端实际 prompt），气泡只展示 `visibleText`。

## 首屏加载过慢

**问题**：首页首屏加载慢，用户等待时间长。

**根因**：`ChatShell` 静态引入 `MemoryStarMapPanel`、`EmailLoginCard`、完整 `ReactMarkdown`，初始还有多个 API 请求。

**修复**：
1. 使用 `next/dynamic` 对重模块懒加载
2. `MemoryStarMapPanel`、`EmailLoginCard` 改为 `ssr: false` 动态加载
3. `ReactMarkdown` 改为 `lazy` 组件
4. 非关键 API 请求后置（账单、审计等）

## 支付宝签名 `invalid-signature`

**问题**：支付宝调起失败，签名校验不通过。

**根因**：签名字符串拼接时遗漏 `sign_type` 参数。

**修复**：严格按支付宝规范拼接签名，签名前将所有参数按 key 字典序排序，`sign_type=RSA2` 参与签名计算。

## 环境变量未生效（`.next` 缓存）

**问题**：修改 `env2` 后重新构建，但前端行为未变化。

**根因**：Next.js `.next` 缓存中保留了旧的编译结果和内联环境变量。

**修复**：`rm -rf .next` 后重新构建。

## 左栏展开溢出

**问题**：左侧面板第一个 item 展开后，内容溢出下方。

**根因**：展开区 `overflow` 处理不当，未对子元素设置 `overflow-y: auto`。

**修复**：对展开内容区设置 `overflow-y: auto` 并限制 `max-height`。

## 记忆分片过长

**问题**：记忆碎片文本过长，没有正确自然语义分片。

**根因**：Java 侧分片长度阈值设置过于宽松（如 300+）。

**修复**：收紧阈值至 `48 / 180 / 90`，在 Fallback 分片中引入多维语义识别词。

## 左栏引导弹窗未接入

**问题**：点击左侧面板的"记忆"、"探索"等 item 后，没有弹出预置说明弹窗。

**根因**：左侧栏 item 点击事件未接入 suggestion guide 逻辑。

**修复**：复用已有的 `pendingSuggestionChip` 状态，点击 item 时设置 chip 并弹出 guide modal。
