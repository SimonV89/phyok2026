# 工程约束

> 所有任务开始前必读的硬性约束，违反将导致安全漏洞、数据不一致或生产故障。

## 核心约束

### 1. 敏感信息保护（最高优先级）

- `env2` 及 `env2.*` 文件**严禁提交至 Git**
- 严禁在代码中硬编码任何真实或测试凭据
- 所有凭据和测试配置**必须通过环境变量管理**
- 根目录 `.gitignore` 已排除 `env2` 和 `env2.*`
- `chat-v2-history.json` 等本地运行数据需加入 `.gitignore`
- `.local-data` 目录（投诉反馈本地工单存储）需排除

**正确做法**：所有凭据从 `process.env` 读取，代码中零硬编码。

### 2. CMS 管理员凭据

- `CMS_ADMIN_USERNAME`、`CMS_ADMIN_PASSWORD`、`CMS_AUTH_SECRET` 必须配置在 `env2` 中
- 严禁在代码或提交中硬编码
- CMS 要求独立的账号密码保护与服务端会话管理

### 3. 计费幂等（最高优先级）

- **仅在大模型成功结束调用时扣减 1 次额度**
- 登录用户默认赠送 20 次
- 计费扣减**必须通过 `runId` 实现幂等**
- 必须通过 `billing_usage_record` 表记录 `runId` 来保证幂等
- 防止前端重试或流式中断导致的额度重复扣减

### 4. 身份路由一致性

- `node2` 必须从鉴权 Token 中提取真实 `userId` / `appId` 并透传至后端服务
- 严禁在读写链路中使用不一致的身份信息
- 必须透传的服务：`memory-service`、`billing-service`、`payment-service`、`audit-service`

### 5. 数据库变更规范

- 各微服务使用 **Flyway** 进行版本管理
- Java 侧 ORM 强制使用 **MyBatis + XML Mapper**
- 当 Flyway 历史记录与业务表状态冲突导致 500 错误时：
  - 优先恢复仓库迁移脚本
  - 或直接 Drop 历史表及相关表后重启服务触发重新迁移
