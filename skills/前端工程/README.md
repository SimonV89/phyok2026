# 前端工程

> 涉及前端 UI、交互、样式时必须遵守的规范。

## UI 规范（最高优先级）

### 文案要求

- **严禁在用户界面中出现"开发文案"或技术术语**
- 禁止出现：`BFF`、`SES`、`审计`、`sessionId`、`参考旧版规则`、`有效调用`（改为"次有效调用"）
- 界面文案必须**完全本地化（中文）**
- 严禁在正式 UI 中出现英文残留（如标签、相似度提示等）
- 所有文案必须**面向真实用户，专业且自然**

### 视觉风格

- 追求"大厂感"和"工业级"质感（如 Codex、Trae、Cursor）
- 讨厌 demo 感或过度修饰性 AI 感
- 极致简约的界面，"节制感"的动效
- 动效需缓慢、自然且具有交互反馈

### 布局密度

- 偏好**高密度的排版布局**
- 紧凑的行高与段间距（如 14px 字号、1.48 行高）
- SSE Markdown 输出要求极致的信息密度

### H5 Drawer 规范

- 必须从屏幕**右侧滑出**（经典 drawer 形式）
- 使用 `translateX` 动画，禁止居中浮层
- 宽度限制：`min(86vw, 368px)`
- 移动端优先

## 首屏性能优化

必须采用的优化手段：

1. **SSR**：页面级 SSR 骨架，避免纯 CSR 白屏
2. **动态加载**：使用 `next/dynamic` 对以下模块按需加载：
   - `MemoryStarMapPanel`（记忆星图）
   - `EmailLoginCard`（邮箱登录）
   - `ReactMarkdown`（Markdown 渲染器）
3. **懒加载配合 Suspense**：占位骨架提升感知速度
4. **非关键逻辑后置**：历史恢复、账单查询等在 idle 或 interaction 后触发

## SSE Markdown 排版

- 最终回答区 Markdown 容器必须显式设置 `white-space: normal`
- 防止继承 `pre-wrap` 导致的冗余空行
- 段间距：`5px`；行高：`1.48`
- 列表缩进：左侧 `15px`

## 动效规范

### 浮云意图文字

围绕输入框的浮云意图文字必须具备：

- **随机漂动**：每帧缓慢位移，有物理感
- **碰撞回弹**：云朵之间碰撞后有克制的小动效
- **Hover 暂停**：Hover 时停止漂动
- **分层视觉**：近实远虚、近大远小
- **严禁重叠**：浮云不得与输入框主体重叠
- **随机初始角度和位置**：每次进入首页重新计算

### 通用动效原则

- 缓慢、自然
- 具有交互反馈
- 布局有错落的围绕感
- 基于距离核心（输入框）远近的视觉分层

## 可视化交互

- 记忆星图等图表必须支持：
  - 单指/鼠标拖拽移动
  - 双指/滚轮缩放
  - 视角复位
- 过程摘要"低干扰"：主回答优先，思维过程次级可展开

## 登录入口逻辑

- 未登录状态下，右上角入口也应显示**下拉菜单**
- 菜单包含"关于"等选项
- 首项为"**立即登录**"
- 禁止直接弹出登录框

## Chat Shell 引导文案脱敏

- 从引导弹窗（记忆/探索）进入聊天时
- 应优化掉原本作为系统提示词的中间过程文案
- 将**可见气泡文案**与**后端实际 kickoff prompt** 拆开
- 确保用户看到的"你"的内容自然且非技术化

## 左栏引导交互

- 点击左侧面板的"记忆"、"探索"等二级菜单项
- 应弹出与输入框周围小动效一致的**预置说明弹窗（Guide Modal）**
- "继续下一步"按钮引导进入聊天
